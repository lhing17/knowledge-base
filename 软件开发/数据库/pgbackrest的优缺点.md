| 分类         | 优点                                                              | 缺点 / 注意事项                                    |
| ---------- | --------------------------------------------------------------- | -------------------------------------------- |
| **功能性**    | - 支持全量、增量、差异备份<br>- 支持 PITR（时间点恢复）<br>- 支持压缩和加密<br>- 可以备份大规模数据库 | - 功能丰富导致学习曲线陡峭<br>- 恢复流程相对复杂，需要严格按文档操作       |
| **性能**     | - 增量/差异备份节省存储和时间<br>- 支持并行备份提高速度                                | - 大规模全量备份仍消耗大量 CPU / I/O<br>- 并发备份可能影响数据库性能  |
| **可靠性**    | - 与 WAL 紧密结合，保证数据一致性<br>- 支持远程仓库和冗余存储                           | - 增量备份依赖 WAL 日志，如果 WAL 丢失或损坏，恢复可能失败          |
| **部署与兼容性** | - 适用于 Linux/Unix 系统<br>- 支持容器化部署                                | - 对文件权限和目录结构敏感<br>- Windows 原生不支持，需要 WSL 等环境 |
| **管理与运维**  | - 提供日志、校验和监控功能<br>- 支持自动清理旧备份                                   | - 配置较复杂（stanza、repo、路径、权限）<br>- 排错需要熟悉内部机制   |
| **社区与文档**  | - 官方文档详尽<br>- 社区活跃                                              | - 边缘场景案例有限<br>- 新手上手难度较高                     |
